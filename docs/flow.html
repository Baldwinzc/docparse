单据解析流程

先对齐这三张图，再写代码、再建仓。主链路是固定流水线；模型只作为某一步里的云 API；持久化先留口子。

不是 Agent步骤顺序写死，不引入 LangChain / LangGraph
只走云 API不部署本地 LLM / VLM / OCR 大模型
持久化预留本阶段内存实现，接口按 Postgres + 对象存储留
字段仍占位等需求方给 PDF / 压缩包和字段清单

主链路

同步视角 自动通过 待复核

一份上传从接入走到结构化结果。压缩包先安全拆开，再和单文件走同一条解析链路。没有证据的字段不能自动通过。

字段抽取

主链路 H 的展开 规则优先 LLM 兜底

按字段表逐个处理。规则能抽到就不调模型；只有字段允许 LLM、且已配置 API Key 时才走云接口。抽到的值必须带回原文证据。

任务时序

异步视角 JobStore / FileStore

调用方拿到 job_id 后查询结果。当前 API 默认同步跑完再返回；后台异步是同一条流水线，只是返回时机不同。

sequenceDiagram
    actor U as 调用方
    participant API as FastAPI
    participant Jobs as JobStore
    participant Files as FileStore
    participant P as 固定流水线
    participant LLM as 云 LLM API

    U->>API: POST /v1/jobs
    API->>Files: 存原始文件
    API->>Jobs: 创建 queued
    API-->>U: job_id
    API->>P: run
    P->>P: unpack / parse / classify / extract / validate
    opt 规则不够
        P->>LLM: 局部文本 + JSON Schema
        LLM-->>P: value + quote
    end
    P->>Jobs: succeeded / needs_review / failed
    U->>API: GET /v1/jobs/{id}
    API-->>U: 状态 + 字段 + 证据
